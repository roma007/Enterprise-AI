## [0.21.0] · 2026-11-02 · 撤销与修订流水（B2）

### 新增
- `run_revisions` 表：append-only，记录 `confirm` / `undo` 的完整前后快照
- `POST /api/runs/{id}/undo`：撤销一次确认（**仅管理员**）
- `GET /api/runs/{id}/revisions`：查看一张单的修订历史
- `GET /api/runs/confirmed`：最近已确认、可撤销的单据
- `/history` 页面：确认历史 + 修订明细 + 撤销按钮
- 工作台确认成功后，管理员会看到「撤销确认」按钮
- `GET /api/audit/{id}` 现在附带 `revisions`

### 撤销做了什么
| 对象 | 变化 |
|---|---|
| `runs` | `confirmed=0`、`confirmed_by=''`、`handle_ms/forced` 清空、`version+1` |
| `feedback` | 删除该单的修正明细（被撤回内容完整保存在 `before_json`） |
| `learn_queue` | 金标回到 `pending`，`gold_json` 清空 |
| `run_revisions` | **追加**一条 `undo`，不删任何历史 |

### 设计取舍
- **撤销不是删除**：确认这个动作发生过，删记录等于篡改审计；
  所以只追加反向流水，`before_json` 保存被撤回的字段与金标
- **feedback 直接清空而不是打作废标记**：修正率、字段准确率都按 feedback 统计，
  留一条"已作废但仍在表里"的记录，早晚污染某个没加过滤的查询
- **乐观并发**：撤销可带 `version`，期间有人重新确认则 409，避免撤错版本
- **条件更新**：`WHERE confirmed=1`，两个人同时点撤销只有一个成功
- **仅管理员**：撤销影响已确认数据与金标，单证员/财务越权返回 403

### 实测
- 确认 → revision `confirm v1`；撤销 → `undo v2`，feedback 清空，金标回 pending
- 重复撤销 409；版本不匹配 409；单证员撤销 403
- 撤销后可重新确认（version 3），审计里能看到 confirm→undo→confirm 全链路
- 指标一致：撤销后 `tickets_confirmed=0`、`labeled=0`
- 页面：历史列表、修订展开、撤销 toast 均正常，无控制台报错
- smoke 9 项全绿；三样本集回归未变

## [0.20.0] · 2026-11-02 · 对象存储抽象（A6）

### 新增
- `app/storage.py` 拆成两套后端，对外接口不变：
  · `local`：`data/uploads/<scope>/<日期>/<随机名>.<ext>`
  · `s3`：AWS S3 / MinIO / 阿里云 OSS / 腾讯云 COS（S3 兼容）
- `STORAGE_BACKEND` / `STORAGE_DIR` / `S3_BUCKET` / `S3_PREFIX` /
  `S3_ENDPOINT_URL` / `S3_REGION` 环境变量
- `GET /api/storage` 增加 `health`：local 看目录是否存在，s3 走 `head_bucket`
- `scripts/test_storage.py`：两条后端路径的自检

### 设计取舍
- **boto3 是可选依赖**：单机客户不该为 10MB 依赖买单；
  `STORAGE_BACKEND=s3` 但没装 boto3 时，上传返回 **503 +「pip install boto3」**，
  不是启动成功、上传时才 500
- **S3 读取由服务端代理**，不返回预签名 URL：私有化部署时客户端网络
  往往到不了存储端点；代价是文件进内存，托书/发票体量可接受
- **数据库里只存相对路径**，换后端不用迁移 `runs.source_file`
- S3 key 由服务端生成，不接受用户输入，避免覆盖他人对象

### 实测
- local：回读逐字节一致、穿越 404、usage/health 正常
- s3（内存假客户端）：key 前缀、ContentType、读回、分页统计、head_bucket 全通过
- s3 未装 boto3：上传与 `/api/storage` 均 503，提示明确
- smoke 8 项全绿；三样本集回归未变

## [0.19.0] · 2026-11-02 · 存原图与批量取消（A4 + A5）

### 新增
- `app/storage.py`：原件存储抽象
  · `local` 后端落 `data/uploads/<scope>/<日期>/<随机名>.<ext>`
  · 扩展名白名单（图片/PDF/文本/表格），其余存为 `.bin`，防止上传 html/svg 做 XSS
  · `resolve()` 校验路径前缀，禁止目录穿越
  · `STORAGE_DIR` / `STORAGE_BACKEND` 环境变量可切换（s3 后端留待 A6）
- `runs.source_file` 记录原件相对路径
- `GET /api/files/{rel}` 回读原件（审计用）
- `GET /api/storage` 查看占用（文件数、字节数）
- `POST /api/batches/{id}/cancel` 取消批量处理

### 设计要点
- **取消是协作式**：处理完当前这一条就停，剩下的保持 `pending`，可随时点"开始处理"续跑；
  不做强杀线程，避免写到一半的脏数据
- **回读走同一套鉴权**：`/api/files/*` 不是公开路径，未登录拿不到原件

### 实测
- 上传 PNG → `source_file` 有值，回读 98283 字节，与原文件**逐字节一致**
- `GET /api/files/../../.env` → 404（目录穿越被拦）
- 60 个文件批次：点取消后 `extracted:2 / pending:58`；再续跑 → `extracted:60`
- smoke 8 项全绿；三样本集回归 100% / 98.7% / 100% 未变

## [0.12.0] · 2026-11-02 · 三单匹配（订单 ↔ 运单 ↔ 发票）

### 新增
- `app/threeway.py` + `/threeway` 页面 + `/api/threeway/*`
- 四个维度：
  · **箱号**（硬）订单与运单的箱号集合必须一致，缺哪个会点名
  · **金额**（硬）发票价税合计 vs 运单应收，超 1% 或 1 元即阻断
  · **客户**（软）订单客户 vs 发票抬头，支持简称/全称包含匹配
  · **箱量**（软）订单箱量 vs 实际箱号数
- 支持传原文，服务端先分别抽取（托书抽取器 + 发票抽取器）再匹配
- 结论三档：pass / review / blocked，对应「可付款 / 需确认 / 不可付款」

### 实测
- 正常一致 → pass（4 个维度全 match）
- 金额差 200 元（8.33%）→ blocked
- 运单少一个箱号 → blocked，并点名缺 `TCLU1234568`

## [0.10.0] · 2026-11-01 · 脱敏与批量导入（采集链路提速）
