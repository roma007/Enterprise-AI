# 行业包热切换实施计划（AI-61）

> 日期：2026-11-20 ｜ 状态：**已完成（AI-61）**
> 目标：设置页激活/回滚后，**新请求立即使用新包，不重启服务**；同一请求/后台任务内部始终使用同一个包版本。

---

## 1. 现状问题

当前 pack 的字段/规则/口径在模块 `import` 时被算成模块常量：

```python
# schema.py
PACK = active_pack()
SPECS = PACK.documents["booking"]
FIELD_KEYS = tuple(s.key for s in SPECS)

# extract.py
from .schema import SPECS, FIELD_KEYS
```

`from ... import CONST` 是**按值绑定**：后面把 `schema.SPECS` 重新赋值，`extract.SPECS` 仍指向旧对象。
`invoice` / `rules` / `reconcile` / `aging` / `fees` / `margin` / `settlement` / `address_check` 也一样。

`pack.reload_pack()` 目前只换 `pack._cache`，不会更新这些常量。强行切会出现：

> 规则已用新包，抽取还在用旧字段；`/api/meta`、批处理、发票、对账各看各的 → 半状态。

盘点时还发现一个 Step 2 回归：`consistency.py` 仍 import `reconcile._containers`，而 Step 2 已改名为 `_values_for`。本任务一并修复。

## 2. 设计

### 2.1 全局当前包 + 活动请求闸门

| API | 作用 |
|---|---|
| `active_pack()` | 全局当前包；`reload_pack()` 原子替换这个引用 |
| `request_guard()` | 请求/任务期间持有“读闸”；期间禁止换包 |
| `reload_pack(pack_id)` | 先加载新包；**无活动请求/任务时**才原子替换并刷新；有活动请求则抛 `PackBusy`（API 返回 409） |

这样：

- 请求/任务运行期间，包不会被换掉，严格保证一个请求内不混包；
- 切换只在“没有请求/任务在跑”的瞬间发生，刷新是内存操作，毫秒级；
- 新请求在切换的瞬间短暂等待，之后看到新包；
- 有长任务在跑时，切换返回“稍后重试”，管理员不会把系统切成半状态。

> 为什么不用“每请求快照”：这个仓库有 160+ 处 `from .schema import CONST` 的按值绑定，
> 改成每请求快照要逐个改消费方；活动闸门只改边界，风险小得多。

### 2.2 兼容层：原地刷新

不改 160+ 处 `from .schema import ...`，而是把模块常量改成**可变容器**（list / dict / set），
切包时**原地 clear/update**。已经 import 的模块看到的是同一个对象，自然拿到新内容。

各模块注册 `refresh(pack)` 监听器：

| 模块 | 刷新内容 |
|---|---|
| `schema` | `SPECS` / `FIELD_KEYS` / `LABELS` / `SPEC_MAP` / `BLOCKING_KEYS`；`PACK_ID` / `PACK_VERSION` 重绑 |
| `invoice` | `INVOICE_SPECS` / `INVOICE_KEYS` / `INV_LABELS` / `INV_SPEC` / `INV_BLOCKING` |
| `rules` | `VALID_TYPES`（set）、`RISK_KEYS`（list）；正则/阈值改为运行时从 pack 取 |
| `reconcile` | `_SPEC` / `_HINTS` / `POSITIONAL_DEFAULT` / `SYSTEM_AMOUNT_FIELDS` / `STATUS_LABELS` / `_MATCH_KEYS` / `_MULTI_KEYS` |
| `statement` | `_STATEMENT_SPEC` / `LINE_HINTS` |
| `aging` | `_HINTS` |
| `fees` | `BUILTIN_FEES`（set）、`_HINTS` |
| `margin` | `_REVENUE_HINTS` / `_COST_HINTS` |
| `settlement` | `_RATE_HINTS` / `_BILL_HINTS` |
| `address_check` | `DISTRICTS` / `_AMBIGUOUS` / `CITY_ALIASES` / `TERMINALS` / `TYPOS` / `PLACE_WORDS` / `TOWNS` |
| `thresholds` | `rules.required` 的 default 跟随当前包的 blocking keys；`rules._required_fields` 过滤新包不存在的 key |

不可变值（编译后的正则、字符串常量）不在运行时依赖；需要的地方用 `current_pack()` 现取。

### 2.3 请求/任务闸门

- FastAPI 中间件：除 `/api/packs/activate`、`/api/packs/rollback` 外，每个请求进入 `request_guard()`。
  - 切换期间新请求短暂等待（`_switching`），切换完成后继续。
  - activate/rollback 自己不能持有读闸，否则会死锁。
- 后台：
  - `batchproc` 每个 job 进入时 `with pack.request_guard():`；
  - `wecom` 图片消息处理走 `extract`，同样包一层；
  - TMS / PDF / notify 若不依赖 pack 字段，可不包；为一致性，worker 循环入口统一包一层。
- 有活动请求/任务时，`reload_pack()` 抛 `PackBusy`，API 返回 409：
  “有请求或任务正在处理，请稍后重试”。不阻塞、不半切。

### 2.4 API / UI

- `POST /api/packs/activate`：写 state → `reload_pack(id)` → 返回 `restart_required: false`，`running == active`。
- `POST /api/packs/rollback`：写 state → `reload_pack()` → 同上。
- 设置页文案：去掉“保存后重启生效”，改为“即时生效”；保留切换历史/回滚。
- `/api/meta`、`/api/packs` 立即反映新包。

## 4. 风险与边界

- **遗漏刷新**：用 hotswap 测试逐项断言；新增字段/规则必须同时更新 `refresh`。
- **后台任务跨切包**：用 `use_pack` 包住 job；v1 不锁定入队版本。
- **`rules.required` 旧值**：过滤当前包不存在的 key，避免切包后必填项引用幽灵字段。
- **多实例**：v1 只保证当前实例即时生效；其他实例需重启，后续可加 PG 通知/定时版本检查。
- **回滚**：`load_pack` 失败时 API 不切换，旧包继续服务；激活指针仍以 state 为准，重启可恢复。
- **性能**：`current_pack()` 是 ContextVar 读取；JSON 只在 reload 时读一次，无每请求 IO。
