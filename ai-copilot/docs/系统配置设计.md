# 智单 · 系统配置功能设计

> 目标：把"现场会改的开关"从代码和 `.env` 里拿出来，让管理员在一个页面里看得懂、改得动、改得住。
> 边界：配置不是功能开关堆砌；**部署级配置（数据库、端口、证书）不进页面**，只做只读展示和指引。
> 读者：产品 / 实施 / 研发 / 客户管理员。

---

## 0. 现状（2026-11-08）

| 已有 | 位置 | 限制 |
|---|---|---|
| 37 项运行级配置 | `/settings` + `data/settings.json`（PG 走 `app_settings`） | 分组导航、变更历史/回滚、开关/列表/模板、导入导出均已具备 |
| 账号与角色 | `/users` | 四角色固定，权限矩阵写死在 `auth.py` |
| 部署配置 | `.env`（LLM / 企微 / 存储 / 登录锁定 / 指标口径） | 页面只读展示 + 连通性测试；改完仍需重启 |
| 登录安全 | `AUTH_TOKEN_TTL`、`LOGIN_*`、密码策略 | 只能改 `.env` |
| 指标口径 | `BASELINE_MANUAL_SEC`、`HOURLY_COST` | 只能改 `.env`，月报跟着变 |

现状的问题不是"项太少"，而是**没有统一入口、没有生效说明、没有变更痕迹**。本设计先解决这三件事，再扩项。

---

## 1. 设计原则

1. **三层配置，各归各位**
   - 部署级：`.env` / 环境变量。改完重启，页面只读展示。
   - 运行级：页面可改，保存即生效（阈值、口径、模板、开关）。
   - 个人级：浏览器本地（列表密度、默认页、折叠状态），不上服务端。
2. **生效方式必须写在界面上**：`即时` / `重启生效` / `下次请求`。
3. **密钥只写不读**：接口永远不返回明文，只返回"是否已配置 + 掩码 + 最后更新时间"。
4. **改得动也要改得住**：每次保存记录 谁 / 何时 / 旧值 → 新值 / 原因，可回滚。
5. **只把"现场真的会调"的项放进页面**：需要改代码逻辑的，不进配置中心。
6. **默认值就是演示口径**：页面明确标"默认值仅用于演示，客户现场必须校准"。

---

## 2. 配置分层

| 层 | 存储 | 谁改 | 生效 | 典型项 |
|---|---|---|---|---|
| 部署级 | `.env` / 环境变量 | 实施 / 运维 | 重启 | `DB_PATH`、`STORAGE_BACKEND`、`COOKIE_SECURE`、`AUTH_SECRET`、`METRICS_TOKEN` |
| 运行级 | `data/settings.json` / `app_settings` | 管理员 | 保存即生效 | 置信度阈值、金额容差、账龄分档、月报口径、告警阈值 |
| 集成级 | `.env` + 页面测试 | 管理员 + 实施 | 重启 / 测试后 | 模型网关、企微应用、S3 |
| 个人级 | `localStorage` | 本人 | 立即 | 列表密度、默认落地页 |

> 运行级配置在多实例下走 PG `app_settings`，最长 2 秒同步；SQLite 单机走文件 + mtime 缓存。

## 5. 交互与安全规则

1. **保存前校验**：类型、范围、依赖（如 `risk_auto_floor` 必须 ≥ `low_conf_floor`）；错误定位到字段，不整页报错。
2. **危险项二次确认**：降低自动通过率、关闭规则、轮换密钥、清空数据，必须输入原因并确认。
3. **密钥只写**：输入框为空表示"不修改"；提供「轮换」，保存后旧值立即失效并记审计。
4. **测试连接**：模型 / 企微 / 存储 / 通知各一个，结果写审计（只记成功失败和耗时）。
5. **变更历史**：按配置项列出时间、操作人、旧值 → 新值、原因；支持回滚到任一历史版本（密钥除外，只能轮换不能回滚）。
6. **导入 / 导出**：导出 JSON 默认不带密钥；带密钥导出需要重新输入密码。
7. **环境差异提示**：同一项同时存在 `.env` 和页面值时，标出"以页面为准 / 以环境变量为准"，避免现场改了半天不生效。
8. **未保存离开提醒**：有改动时离开页面弹确认。

## 6. 数据模型

```sql
config_items (
  key         TEXT PRIMARY KEY,
  value_json  TEXT NOT NULL,
  updated_by  TEXT NOT NULL,
  updated_at  TEXT NOT NULL,
  version     INTEGER NOT NULL DEFAULT 1
);

config_history (
  id          TEXT PRIMARY KEY,
  key         TEXT NOT NULL,
  old_json    TEXT,
  new_json    TEXT,
  actor       TEXT NOT NULL,
  reason      TEXT,
  source_ip   TEXT,
  ts          TEXT NOT NULL
);
```

- **单租户**：智单是客户交付系统，不设 `org_id`；多客户 = 多实例独立部署。
  只有将来决定把智单改成 SaaS 形态时，才重新评估租户隔离；当前不做。
- `config_items` 只存运行级配置；部署级仍以 `.env` 为准。
- 模型 / 企微 / 存储密钥不落 `config_items`，继续放 `.env`，页面只读展示。
- 通知 Webhook 目前存 `data/settings.json`（接口返回脱敏、导出跳过）；
  若客户要求密钥集中管理，再迁受管密钥存储。
- SQLite 单机可以继续用 `data/settings.json`；多实例必须 PG。

## 7. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/config` | 分组返回，密钥掩码，带 `source`（default/env/page） |
| PUT | `/api/config` | 批量保存，带 `version` 乐观锁；失败返回冲突字段 |
| POST | `/api/config/reset` | 按组 / 按 key 恢复默认（需原因） |
| POST | `/api/config/test/{target}` | `llm` / `wecom` / `storage` / `notify` |
| GET | `/api/config/history?key=` | 变更历史 |
| POST | `/api/config/rollback/{id}` | 回滚（密钥类拒绝） |
| GET | `/api/config/export` | 导出 JSON（默认脱敏） |
| POST | `/api/config/import` | 导入并校验 |

- 写操作仅 `admin`；`finance` / `operator` 只读对应组；`viewer` 只读。
- 所有写操作写审计，包含旧值掩码后的 diff。
