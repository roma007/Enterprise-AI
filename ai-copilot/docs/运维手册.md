# 运维手册

> 目标：任何人拿到这台机器，30 分钟内能跑起来、能排查、能重置。

## 一之二、登录与账号

| 项 | 说明 |
|---|---|
| 登录地址 | `/login` |
| 初始管理员 | 首次启动时创建，邮箱/密码取 `.env` 的 `ADMIN_EMAIL` / `ADMIN_PASSWORD`；未配置则随机生成并**只在控制台打印一次** |
| 角色 | `admin` 全部 · `operator` 托书与批量 · `finance` 发票/对账/账龄/外协 · `viewer` 只读 |
| 用户管理 | `/users`（仅管理员） |
| 强制下线 | 停用用户，或用户自己改密码（踢掉其他设备） |
| 重置密码 | 管理员停用再启用会踢下线，但不会重置密码；忘记密码时用 SQL 或重新初始化 |

**必配环境变量**

```env
ADMIN_EMAIL=admin@local
ADMIN_PASSWORD=至少10位且含字母数字
AUTH_SECRET=生产环境务必设置（不设则落盘到 data/auth_secret）
AUTH_TOKEN_TTL=43200      # 令牌有效期（秒），默认 12 小时
```

> `data/auth_secret` 与 `.env` 一样是敏感文件，**不进版本库**。

## 一之四、原件与批量

### 原件存储（A4）

| 项 | 说明 |
|---|---|
| 位置 | `data/uploads/<booking\|invoice>/<YYYYMMDD>/<随机名>.<ext>` |
| 记录 | `runs.source_file` 存相对路径 |
| 回读 | `GET /api/files/{rel}`（需登录，非公开路径） |
| 占用 | `GET /api/storage` |
| 后端 | `STORAGE_BACKEND=local`（默认）/ `s3` |
| 备份 | 与 `copilot.db` 一起备份，**两者必须成对**，否则回读到空 |

**切到 S3（多实例/集中备份时）**

```bash
pip install boto3          # 可选依赖，不用 S3 不必装
```

```env
STORAGE_BACKEND=s3
S3_BUCKET=your-bucket
S3_PREFIX=uploads/
S3_ENDPOINT_URL=https://oss-cn-hangzhou.aliyuncs.com   # MinIO 填内网地址；AWS 留空
S3_REGION=cn-hangzhou
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
```

| 注意 | 说明 |
|---|---|
| 只存相对路径 | 库里是 `booking/20261102/xxx.png`，换后端不用改数据 |
| 读取走服务端代理 | 不返回预签名 URL，客户端不需要能访问存储端点 |
| 连通性自检 | `GET /api/storage` 的 `health.ok` 为 true 才算配好 |
| 权限 | 账号至少需要该前缀的 `PutObject` / `GetObject` / `HeadObject` / `ListBucket` |
| 迁移 | 老数据留在本地时，可先保持 `local`，或把 `data/uploads/` 整体同步到桶内同前缀 |

> 单张上传（托书/发票）会存原件；批量导入的图片已由批次目录留存，走 `data/batches/`。

### 批量取消（A5）

| 项 | 说明 |
|---|---|
| 入口 | 批次页「取消」按钮，或 `POST /api/batches/{id}/cancel` |
| 行为 | 协作式：处理完当前一条就停，其余保持 `pending` |
| 续跑 | 再点「开始处理」，从 pending 继续 |
| 注意 | 取消不是回滚，已抽出的记录仍在库里 |

## 一之五、撤销与修订流水

| 项 | 说明 |
|---|---|
| 入口 | `/history`（管理员可撤销） |
| 接口 | `POST /api/runs/{id}/undo`，body `{"note":"原因","version":3}` |
| 权限 | 仅 `admin`；单证员/财务调用返回 403 |
| 可撤销窗口 | 不限制时间；列表默认最近 100 条 |
| 撤销后 | 该单回到未确认，修正明细清空，金标回到待标注 |
| 历史 | `run_revisions` 只追加不删除，审计接口会一并返回 |
| 并发 | 带 `version` 时，若期间有人重新确认会返回 409，刷新后再操作 |

> **撤销 ≠ 回滚到某个旧版本**。当前只支持"撤销最近一次确认"；
> 历史字段值保留在修订流水里供查证，但不会自动写回 `fields_json`。

## 一之六、学习队列（越用越准）

| 项 | 说明 |
|---|---|
| 入口 | `/learn`（单证员 / 财务 / 管理员；只读账号只能看） |
| 来源 | 低置信、有阻断、容错抽取、多票切分自动入队；人工确认也会产出一条 |
| 标注 | 字段预填系统值，改过的保存为「难例」；也可整条跳过 |
| 导出 | 页面「导出 JSONL」，或 `GET /api/learn/export.jsonl` |
| 入评测集 | 追加到 `samples/bookings.jsonl`，再跑 `scripts/run_eval.py` |
| 记录 | `labeled_by` + `run_revisions`（标注/跳过都可追到人） |

> **标注 ≠ 确认。** 标注只改 `learn_queue` 的金标，不动 `runs.confirmed`；
> 已确认的单仍以确认时提交的字段为准。

**建议节奏**：每周清一次待标注队列，优先看「阻断」和「低置信」；
难例数量比标注总数更有意义——全是原样确认说明规则已经够用。

## 一之七、企业微信接入

| 模式 | 配置 | 用途 |
|---|---|---|
| 明文 | 只配 `WECOM_TOKEN` | 本地调试；消息体不加密 |
| **安全** | `WECOM_TOKEN` + `WECOM_ENCODING_AES_KEY` + `WECOM_CORPID` | 生产必须 |

```env
WECOM_TOKEN=企业微信后台「接收消息」里的 Token
WECOM_ENCODING_AES_KEY=43 位，后台随机生成
WECOM_CORPID=企业 CorpID（安全模式下用于 receiveid 校验）
```

```bash
pip install cryptography   # 安全模式的可选依赖
```

| 检查 | 方法 |
|---|---|
| 依赖是否装好 | `PYTHONPATH=. .venv/bin/python scripts/test_wecom_crypto.py` |
| 配置是否齐全 | 缺任一项时回调返回 503，并列出缺哪个变量 |
| 回调地址 | `https://你的域名/api/wecom/callback` |
| 权限 | 该路径公开（用企微自己的签名校验），不需要登录 |

> 安全模式下**不要**把 Token 留空：服务端会拒绝启动回调（503），
> 否则任何人都能伪造消息进来。

## 一之八、回写交付平台

| 项 | 说明 |
|---|---|
| 入口 | 工作台「评测结果」卡右侧「回写交付平台」（仅管理员） |
| 接口 | `POST /api/delivery/push`、`POST /api/delivery/flush`、`GET /api/delivery/status` |
| 结果 | 在交付平台 POC 页面的「运行记录」里生成一条 `poc_run` |
| 幂等 | 同一份评测结果重复点，不会生成第二条 |
| 重试 | 后台每 `DELIVERY_RETRY_SECONDS` 秒重试 pending；4xx 记永久失败 |

```env
DELIVERY_PLATFORM_URL=http://127.0.0.1:8788
DELIVERY_HOOK_TOKEN=与平台 COPILOT_HOOK_TOKEN 一致
DELIVERY_EXPERIMENT_ID=目标 POC 实验 uuid
DELIVERY_RETRY_SECONDS=60
```

平台侧：

```env
COPILOT_HOOK_TOKEN=与上面 DELIVERY_HOOK_TOKEN 一致
```

| 排查 | 方法 |
|---|---|
| 回写没配置 | `GET /api/delivery/status` 看 `missing` |
| 平台 401 | 两侧 token 不一致 |
| 平台 404 | `DELIVERY_EXPERIMENT_ID` 不是有效实验 |
| 平台 503 | 平台没配 `COPILOT_HOOK_TOKEN` |
| 一直 pending | 看 `recent[].last_error`；网络/5xx 会自动重试 |

> 回写内容只包含评测指标与版本，**不包含托书原文和客户数据**。
> 原文留在客户自己的 `copilot.db`，不回传。

## 二、启动与停止

```bash
cd ai-copilot

# 启动（自动优先用 .venv）
make dev
# 等价于：PYTHONPATH=. .venv/bin/python -m uvicorn app.main:app --port 8790

# 停止
pkill -f "uvicorn app.main:app"

# 后台启动并保留日志
PYTHONPATH=. .venv/bin/python -m uvicorn app.main:app --port 8790 \
  --log-level warning > data/server.log 2>&1 &
```

**端口**：默认 8790（避开交付平台的 8788）。

**检查是否活着**

```bash
curl -s localhost:8790/api/health
```

正常返回里应包含：

```json
{"ok":true,"llm_enabled":true,"model":"claude-haiku-5-5",
 "ocr":{"pil":true,"pymupdf":true,"rapidocr":true,"ready":true}}
```

## 七、常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `ModuleNotFoundError` | 用了系统 python 而不是 `.venv` | `make dev`（会自动选 `.venv`） |
| `api/health` 里 `ocr.ready=false` | OCR 依赖没装 | `make setup` 或检查是否 Python 3.11 |
| 上传图片返回 503 | OCR 依赖缺失 | 同上；此时仍可用粘贴文本 |
| `403 error code 1010` | 模型网关拦截 UA | 设 `LLM_USER_AGENT` |
| `400 MissingSessionID` | 缺会话头 | 设 `LLM_SESSION_HEADER=x-opencode-session` |
| 解析变成 5 秒/单 | 模型未命中缓存 | `make prewarm` 预热 |
| 端口被占用 | 上次没退干净 | `pkill -f uvicorn` |
| 指标全是 0 | 数据库被重置 | 正常，重新跑一遍单据 |

## 九、数据口径备忘（对外汇报前必看）

| 指标 | 定义 | 注意 |
|---|---|---|
| 字段级准确率 | 正确字段 / 参与比较字段 | 调优集已饱和，**只报留出集或真实集** |
| 整单完全正确 | 所有字段都对 / 总单数 | 比字段级严格得多 |
| 自动通过率 | `review_level=auto` / 总票数 | 与风险模拟同一口径 |
| 人工修正率 | 被改字段 / 已确认单的非空字段总数 | 分母不是"被改字段数" |
| 节省工时 | Σ max(0, 基线 − 实际确认耗时) | 只用已确认的单 |
| 绕过率 | (入口来单 − 已确认) / 入口来单 | 需要入口接入后才有 |
| 错单率（风险模拟） | `(错单+1)/(样本+2)` | **Laplace 平滑，0 错单不等于 0 风险** |

## 十一、批量导入与脱敏

| 入口 | 用途 |
|---|---|
| `http://127.0.0.1:8790/batch` | 建批次 → 批量上传 → 后台处理 → 看进度 → 重试失败 |
| `POST /api/batches` | 建批次（`kind` 选 `booking` 或 `invoice`，默认托书） |
| `POST /api/batches/{id}/upload` | 一次上传多个文件（≤200 个，单个 ≤10MB） |
| `POST /api/batches/{id}/process?use_llm=false&mask=true` | 启动后台处理 |
| `POST /api/batches/{id}/retry` | 失败重试 |
| `POST /api/mask` | 只做脱敏预览 |
| `GET /api/batches/failed` | 跨批次失败队列 |
| `POST /api/batches/retry-all` | 一键重排失败项 |

**分层抽样**

```bash
# 演示：造台账并抽 400 份
make sample N=400

# 实际：读台账 JSONL（id/month/client/format/filename）
PYTHONPATH=. .venv/bin/python scripts/sample_plan.py   --input 台账.jsonl --target 400 --out 抽样清单.csv
```

清单是带 BOM 的 CSV，Excel 直接打开，打印后交给档案室照着勾。

**脱敏规则**

| 类型 | 处理 |
|---|---|
| 公司/货代名 | → 客户一、客户二…（`data/mask_map.json` 持久映射，同一实体始终同一代号） |
| 联系人姓名 | 张* |
| 手机 / 固话 | `138****5678` / `0574-****6666` |
| 身份证 / 报关单号 / 银行账号 | 等长占位符，保留首尾 |
| 邮箱 | `zh***@domain.com` |

> ⚠️ `data/mask_map.json` 是**可还原的映射表**，包含真实公司名。它已在 `.gitignore` 里，
> 但**绝不能外发**。对外只交付脱敏后的文本与原文指纹。

## 十二、模拟与演练脚本

| 命令 | 作用 |
|---|---|
| `make simday` | 模拟一整天：入口→解析→分级→确认→指标→风险→拆分→改单 |
| `make pairing` | 纸质↔TMS 配对演示 |
| `make goldset` | 弱金标 + 抽检校准演示 |
| `make amend` | 改单 diff 演示 |
| `make enhance` | 图像增强对比演示 |
| `make prewarm` | 预热模型缓存 |

**这些脚本会写数据**，跑完想还原就 `make reset`。
