## 二、启动与停止

```bash
cd ai-copilot

# 启动（自动优先用 .venv）
make dev
# 等价于：PYTHONPATH=. .venv/bin/python -m uvicorn app.main:app --port 8790

# 停止
pkill -f "uvicorn app.main:app"

# 后台启动并保留日志
PYTHONPATH=. .venv/bin/python -m uvicorn app.main:app --port 8790 \
  --log-level warning > data/server.log 2>&1 &
```

**端口**：默认 8790（避开交付平台的 8788）。

**检查是否活着**

```bash
curl -s localhost:8790/api/health
```

正常返回里应包含：

```json
{"ok":true,"llm_enabled":true,"model":"claude-haiku-5-5",
 "ocr":{"pil":true,"pymupdf":true,"rapidocr":true,"ready":true}}
```

## 三、数据在哪、怎么备份

| 文件 | 内容 | 丢了会怎样 |
|---|---|---|
| `data/copilot.db` | SQLite：解析记录、人工修正、金标、入口来单 | 历史与指标全丢 |
| `data/llm_cache.json` | 模型结果缓存 | 只是变慢、重新花钱 |
| `.env` | 模型密钥、企微 Token | 需要重新配 |

```bash
# 备份
mkdir -p backups && cp data/copilot.db "backups/copilot-$(date +%F).db"

# 恢复
cp backups/copilot-2026-11-01.db data/copilot.db
```

**注意**：`data/` 里有客户原文，按 `samples/real/README.md` 的脱敏规范管理。

## 五、环境变量（`.env`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `LLM_BASE_URL` | openai | 模型网关地址 |
| `LLM_API_KEY` | 空 | 空 = 纯规则引擎，仍可运行 |
| `LLM_MODEL` | gpt-4o-mini | 当前用 `claude-haiku-5-5` |
| `LLM_USER_AGENT` | ai-copilot/1.0 | **OpenCode 网关必须非空** |
| `LLM_SESSION_HEADER` | 空 | OpenCode 网关填 `x-opencode-session` |
| `LLM_STRATEGY` | auto | auto / always / off |
| `MERGE_POLICY` | fill_only | fill_only / floor / llm_wins |
| `OCR_ENHANCE` | 1 | 0 = 关闭多版本 OCR |
| `WECOM_TOKEN` | 空 | 空 = 跳过签名校验（仅本地调试） |
| `BASELINE_MANUAL_SEC` | 180 | 人工单票基线秒数（**必须按客户实测改**） |
| `HOURLY_COST` | 45 | 人工小时成本 |
| `DB_PATH` | data/copilot.db | 遥测库路径 |

## 六、密钥轮换

```bash
# 1. 改 .env 里的 LLM_API_KEY
# 2. 清掉缓存（旧缓存仍在，但不会影响正确性，只是不再命中新模型）
rm -f data/llm_cache.json
# 3. 重启服务
pkill -f "uvicorn app.main:app" && make dev
# 4. 验证
curl -s localhost:8790/api/health
make eval        # 确认模型通道正常
```

**不要**把 `.env` 提交到版本库（`.gitignore` 已覆盖）。

## 七、常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `ModuleNotFoundError` | 用了系统 python 而不是 `.venv` | `make dev`（会自动选 `.venv`） |
| `api/health` 里 `ocr.ready=false` | OCR 依赖没装 | `make setup` 或检查是否 Python 3.11 |
| 上传图片返回 503 | OCR 依赖缺失 | 同上；此时仍可用粘贴文本 |
| `403 error code 1010` | 模型网关拦截 UA | 设 `LLM_USER_AGENT` |
| `400 MissingSessionID` | 缺会话头 | 设 `LLM_SESSION_HEADER=x-opencode-session` |
| 解析变成 5 秒/单 | 模型未命中缓存 | `make prewarm` 预热 |
| 端口被占用 | 上次没退干净 | `pkill -f uvicorn` |
| 指标全是 0 | 数据库被重置 | 正常，重新跑一遍单据 |

## 九、数据口径备忘（对外汇报前必看）

| 指标 | 定义 | 注意 |
|---|---|---|
| 字段级准确率 | 正确字段 / 参与比较字段 | 调优集已饱和，**只报留出集或真实集** |
| 整单完全正确 | 所有字段都对 / 总单数 | 比字段级严格得多 |
| 自动通过率 | `review_level=auto` / 总票数 | 与风险模拟同一口径 |
| 人工修正率 | 被改字段 / 已确认单的非空字段总数 | 分母不是"被改字段数" |
| 节省工时 | Σ max(0, 基线 − 实际确认耗时) | 只用已确认的单 |
| 绕过率 | (入口来单 − 已确认) / 入口来单 | 需要入口接入后才有 |
| 错单率（风险模拟） | `(错单+1)/(样本+2)` | **Laplace 平滑，0 错单不等于 0 风险** |

## 十、代码同步（GitHub + Gitee）

| 远程 | 地址 | 分支情况 |
|---|---|---|
| `origin`（GitHub） | `git@github.com:roma007/Enterprise-AI.git` | `main` |
| `gitee` | `git@gitee.com:roma007007/enterprise-ai.git` | `main` 与 `master` **始终同一提交** |

**日常推送**

```bash
git add -A && git commit -m "为什么改"
git push origin main     # GitHub
git push gitee           # 已配置双 refspec，一次同步 main 和 master
```

**为什么 Gitee 有两个分支**

建仓时 Gitee 默认分支是 `master`，而本地是 `main`。Gitee API token 已失效（401），无法用接口改默认分支。
为了保证**不管默认分支是哪个都能看到完整内容**，`gitee` 远程配置了两条 refspec：

```bash
git config --get-all remote.gitee.push
# refs/heads/main:refs/heads/main
# refs/heads/main:refs/heads/master
```

有权限时建议：Gitee → 仓库设置 → 修改默认分支为 `main` → 再删掉 `master`。

**提交前的三条自检**

```bash
git status --short                      # 有没有不想提交的
git ls-files | grep -E '\.env$|\.db$'   # 应为空
git diff --cached --stat                # 改了什么
```

**已知的提交边界**

- `.env`、`data/`、`.venv/`、`node_modules/`、`backups/`、`samples/real/raw|masked` 一律不提交
- `LICENSE` 版权署名当前为 `roma007`（两个远程一致）；要改名字只需改这一行
