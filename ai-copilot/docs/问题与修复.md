# 问题与修复记录

> 每一次"跑出来不对"都记在这里：现象 → 根因 → 修法 → 怎么发现的 → 怎么防复发。
> 目的：下次遇到同样的问题，5 分钟内能定位，而不是重新踩一遍。

---

## 一、抽取逻辑类

### BUG-001 · 箱号正则在中日韩文本里失效

| 项 | 内容 |
|---|---|
| 现象 | `箱号：CSQU3054383` 抽不出箱号 |
| 根因 | 用了 `\b([A-Z]{4}\d{7})\b`。Python 的 `\b` 基于 Unicode `\w`，中文字符也算 `\w`，所以"号"和"C"之间**没有词边界** |
| 修法 | 改成显式环视：`(?<![A-Z0-9])([A-Z]{4}\d{7})(?![A-Z0-9])` |
| 发现方式 | 单元测试跑不通 |
| 防复发 | 所有涉及中英混排的正则，一律不用 `\b` |

### BUG-002 · 行首字段名把冒号设成可选，导致误抽

| 项 | 内容 |
|---|---|
| 现象 | `客户是海通国际` 抽成 `client = "是海通国际"` |
| 根因 | 行首匹配写成 `^客户\s*[:：]?\s*(.+)$`，冒号可选，于是"是海通国际"整段被当成值 |
| 修法 | 行首匹配**必须要求冒号**；无冒号的场景（`客户是…`）走单独的动词模式 |
| 防复发 | 精确路径和模糊路径分开，不要用一个宽松正则兜所有情况 |

### BUG-003 · 短字段名被当子串匹配

| 项 | 内容 |
|---|---|
| 现象 | `客户是海通货代 单号HT-1105` 抽成 `client = "单号HT-1105"` |
| 根因 | 字段名"货代"出现在值"海通**货代**"里，被当成键名匹配上了 |
| 修法 | 键名前面加中日韩边界：`(?<![\u4e00-\u9fa5A-Za-z])` |
| 防复发 | 所有键名匹配都带这个前置断言 |

### BUG-004 · 箱号内部空格 vs 箱号之间的空格

| 项 | 内容 |
|---|---|
| 现象 | `CSQU3054383 TCLU1234568`（两个箱号）被粘成一个；`CSQU 3054383`（一个箱号带空格）被拆成两个 |
| 根因 | 先统一去空格再切分，把两种情况混为一谈 |
| 修法 | 两遍正则：先在原串上抓，再去空格抓，结果合并去重 |
| 发现方式 | 归一化单测 |
| 防复发 | 归属判断靠"能不能匹配标准箱号形态"，不靠分隔符 |

### BUG-005 · "到11月8号"被当成送达地址

| 项 | 内容 |
|---|---|
| 现象 | 改单 `截港延到11月8号18点` 产生假 diff：送达地 → "11月8号" |
| 根因 | 地址动词模式里有 `到…号`（匹配"送到…3号"），而日期也以"号"结尾 |
| 修法 | 地址字段加日期形态排除：含 `\d{1,2}月\d{1,2}号` 或时分的一律丢弃 |
| 发现方式 | 改单模拟演练 |
| 防复发 | 跨字段串扰只能靠真实句式跑出来 —— 每次改动词模式都要跑一遍改单场景 |

### BUG-006 · OCR 把相邻两个字段粘成一个框

| 项 | 内容 |
|---|---|
| 现象 | `品名：家用电器毛重：18600` 被抽成 `cargo_desc = "家用电器毛重:18600"` |
| 根因 | OCR 输出的是文本框，两个字段可能落在同一个框里 |
| 修法 | `_cut_stop`：在"下一个字段名 + 冒号"处截断；并且一行里按连续空格再切一次 |
| 发现方式 | OCR 合成截图实测 |
| 防复发 | 抽取链路要假设"一行里可能有多个字段" |

### BUG-007 · 简写箱型 / 口语箱型不认

| 项 | 内容 |
|---|---|
| 现象 | `40H`、`20尺小柜两个` 抽不出箱型/箱量 |
| 根因 | 只认标准写法 `40HQ` |
| 修法 | 归一表：`40H→40HQ`、`高柜→40HQ`、`小柜→20GP`、`大柜→40GP`；数量词 `两个→2` |
| 发现方式 | 客户模拟集（X1/X2） |

### BUG-008 · OCR 丢失时间分隔符

| 项 | 内容 |
|---|---|
| 现象 | `2026110718:00`、`2026-11-0608:00` 解析失败 |
| 根因 | 时间正则要求完整分隔符 |
| 修法 | 兜底：在纯数字串里滑窗找 12 位 `YYYYMMDDHHMM`，并做合法性校验（月 1–12、时 <24） |
| 发现方式 | 图像增强实验 |

## 二、指标与口径类（**最危险的一类**）

### BUG-101 · 修正率永远 100%

| 项 | 内容 |
|---|---|
| 现象 | 指标中心显示"人工修正率 100%"，客户会认为系统全错 |
| 根因 | 分母写成"被改过的字段数"，分子也是它 |
| 修法 | 分母改为"已确认单的全部非空字段数" |
| 实测 | 100% → **0.4%** |
| 防复发 | 任何比率都要写清分子分母，并在注释里写明 |

### BUG-102 · 同一批数据两个自动通过率

| 项 | 内容 |
|---|---|
| 现象 | 指标中心 66.7%，风险模拟 100% |
| 根因 | 指标中心按 `review_level` 算，风险模拟另算一套置信度阈值 |
| 修法 | 统一用 `review_level == 'auto'` |
| 教训 | **一个系统里两套口径，等于没有口径** |

### BUG-103 · 节省工时算成了"花掉的时间"

| 项 | 内容 |
|---|---|
| 现象 | 月省 933 元（正确应 2,378 元） |
| 根因 | 公式写成 `票量 × 自动通过率 × 平均确认耗时` |
| 修法 | 改为 `票量 × 自动通过率 × max(0, 基线 − 实际)` |
| 差距 | **74 倍** |

### BUG-104 · 0 错单被当成 0 风险

| 项 | 内容 |
|---|---|
| 现象 | 12 单 0 错，风险模拟输出"数据支持取消大部分人工确认" |
| 根因 | 错单率 = `错单/样本`，0/12 = 0 |
| 修法 | Laplace 平滑：`(错单+1)/(样本+2)` |
| 效果 | 0% → 7%，结论从"支持取消"变成"不建议取消" |
| 教训 | **系统不能因为"没见过错"就说"不会错"** |

## 三、工程与交互类

### BUG-201 · `except Exception: pass` 吞掉 NameError

| 项 | 内容 |
|---|---|
| 现象 | 改单反查完全没触发，日志里什么都没有 |
| 根因 | `store.py` 用了 `re` 但没 import；外层 `except Exception: pass` 把 NameError 吞了 |
| 修法 | 补 import；**把 `pass` 改成把错误写进返回值**（`amend.error`） |
| 教训 | 宽泛 except 是排障的最大敌人。宁可暴露 500，也不要静默降级 |

### BUG-202 · 切票时前端崩溃

| 项 | 内容 |
|---|---|
| 现象 | 点"第 2 票"报 `Cannot read properties of null (reading 'checks')` |
| 根因 | `render()` 里先用了 `LAST.checks`，但 `LAST` 在函数末尾才赋值 |
| 修法 | `LAST = d` 提到函数第一行 |
| 发现方式 | 浏览器里真点了一遍（只跑 API 测不出来） |

### BUG-203 · 多票里夹一票改单，被粘成一票

| 项 | 内容 |
|---|---|
| 现象 | `1. 新单… 2. 原单 HY-1105 有变…` 只切出 1 票，且把两票字段混在一起 |
| 根因 | 切分只认 `单号：`，不认 `原单 XX` |
| 修法 | 增加 `AMEND_REF` 正则，把它也当作一票的起点；拆完逐票判断是否改单 |
| 发现方式 | 模拟演练 B2 |

### BUG-204 · 客户名被"这票有变"污染

| 项 | 内容 |
|---|---|
| 现象 | 改单产生假 diff：客户 宏远国际货代 → 宏远国际货代 这票有变 |
| 根因 | 抽取把语气词一起带走 |
| 修法 | 软字段加 `_same_ish` 守卫：一个是另一个的子串且长度差 ≤8 视为相同 |
| 防复发 | 改单 diff 必须能容忍"多几个字"的噪声 |

## 四、环境类

### BUG-301 · Python 3.14 装不上 onnxruntime

| 项 | 内容 |
|---|---|
| 现象 | `pip install rapidocr-onnxruntime` 长时间无进展 / 失败 |
| 根因 | onnxruntime 还没有 cp314 的 wheel |
| 修法 | 用 `uv venv --python 3.11` 建独立环境；Makefile 自动优先用 `.venv` |
| 防复发 | 依赖二进制包的项目，Python 版本要落后主流一个版本 |

### BUG-302 · OpenCode 网关 403 / 400

见 `决策记录.md` ADR-005。要点：UA 必须非空，必须带 `x-opencode-session`。
