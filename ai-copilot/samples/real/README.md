# 真实样本入库规范

> 这个目录**默认不进版本库**（含客户敏感信息）。只放脱敏后的样本与金标。
> 目的：让"评测"这件事可复现——同一个样本集，任何人跑出来的数字必须一样。

---

## 一、目录结构

```
samples/real/
├── README.md            ← 本文件
├── manifest.jsonl       ← 样本清单（id / 来源 / 日期 / 脱敏级别 / 金标状态）
├── raw/                 ← 原始文件（图片/PDF/Excel），仅本机保留
├── masked/              ← 脱敏后的文本或文件，进入评测
└── gold/                ← 金标 JSONL，一行一条
```

---

## 二、三步入库

### 第 1 步：原始样本落地

- 来源文件名 → `raw/<客户代号>-<序号>.<ext>`，例如 `HY-001.jpg`
- **客户代号用两个字母**，与客户真实名称无对应关系，对应表单独保存、不进本目录
- 记录到 `manifest.jsonl`：

```json
{"id":"HY-001","ext":"jpg","source":"微信截图","received":"2026-11-05","masked":false,"gold":false}
```

### 第 2 步：脱敏

必须处理的三类信息（按 `00_总体规划.md` §10 的安全要求）：

| 类型 | 处理 |
|---|---|
| 公司名 / 客户名 / 货代名 | 替换为 `客户A`、`货代B`，替换表单独保存 |
| 手机号 | 中间四位变 `****`，保留后四位可核对 |
| 报关单号 / 身份证 / 银行账号 | 全部替换为等长占位符 |

- 脱敏后存 `masked/<id>.txt`（或保留原格式）
- `manifest.jsonl` 中把 `masked` 改为 `true`
- **脱敏前后各留一份哈希**，用于证明加工过程可追溯

### 第 3 步：金标

一行一个 JSON，字段名必须与 `app/schema.py` 的 `FIELD_KEYS` 完全一致：

```json
{"id":"HY-001","raw":"客户A，40HQ，箱号 CSQU3054383……","gold":{"client":"客户A","container_type":"40HQ","container_no":"CSQU3054383"}}
```

**金标纪律（比什么都重要）**

1. **只标原文里明确有的字段。** 推断出来的不算，宁缺勿滥。
2. **两个人独立标，不一致的当场讨论。** 单人标注的金标 = 没有金标。
3. **看不清就留空。** 不要"大概应该是这个"。
4. **标注人不知道当前规则/提示词怎么写的**，否则会不自觉按系统习惯标（这是评估污染）。
5. 标完在 `manifest.jsonl` 里把 `gold` 改为 `true`。

## 三、评测与对外口径

| 样本集 | 用途 | 能不能对外讲数字 |
|---|---|---|
| `samples/bookings.jsonl`（20 份） | 调优 | ❌ 只能作对照 |
| `samples/bookings_holdout.jsonl`（8 份） | 自造留出 | ❌ 说明"自造，偏乐观" |
| `samples/real/masked/`（≥200 份） | **真实评测** | ✅ 标注样本量与日期后可讲 |

**对外只讲真实集。** 且必须同时给出：样本量、采集日期、字段级准确率、整单完全正确率、人工修正率。
