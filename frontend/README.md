# 企业 AI 化项目管理系统 · 内部工作台

Vite + React 19 + TypeScript。接后端 Fastify API，覆盖 S1 诊断阶段的录入、校验与报告生成。

## 运行

```bash
# 先起后端（8788）
cd ../backend && npm run dev

# 再起前端（5173）
npm install
npm run dev        # http://127.0.0.1:5173
```

`vite.config.ts` 已把 `/api` 代理到 `http://127.0.0.1:8788`，开发时不需要 CORS。生产可改为网关反代，或设置 `VITE_API_BASE`。

## 页面

| 路由 | 内容 |
|---|---|
| `#/` | 项目列表、统计、新建客户/项目 |
| `#/engagements/:id` | 项目详情，16 个页签 |
| `#/knowledge` | 知识库：全文/分类/行业/标签/有效期检索，审批发布与退回 |
| `#/login` | 登录（演示账号 `zhang@hengzhi.ai` / `demo1234`） |
| `#/share/:token` | 客户只读分享页：无需登录，查看/下载已批准交付物 |
| `#/benchmarks` | 行业标杆维护：p25/p50/p75、来源、年份、校准状态 |
| `#/trash` | 回收站：客户/项目/交付物按批次恢复 |
| `#/audit` | 审计日志：写操作、对象、状态、操作人、请求 ID、IP；服务端分页；热表/归档切换与归档预演 |
| `#/sessions` | 登录会话：设备/IP/时间，撤销单个会话、全部退出、自助修改密码 |
| `#/users` | 用户管理（管理员/总监）：创建、角色、状态、重置密码 |

项目详情页签：

- **概览**：机会点/痛点/基线统计、G0–G5 门禁、14 项一致性校验、机会点表、局限分流
- **干系人与访谈**：录入/删除干系人、访谈
- **痛点**：录入/删除/CSV/Excel 导入痛点，显示来源覆盖率与 G1 缺口
- **四维盘点**：业务/数据/系统/组织分组，JSON 属性，完整度，CSV/Excel 导入
- **业务流程**：节点/连线只读展示，JSON 整图替换，确认人
- **机会点与 ROI**：机会点列表、CSV/Excel 导入、评分编辑、基线、ROI、传导链、收益形态确认、关联痛点
- **方案设计**：G2 门禁、方案版本、组件、集成、工作量、验收标准、评审、生成方案文档
- **报价**：报价版本、一次性/年运维行、汇总、导出 Word、生成报价单交付物
- **POC 验证**：G3 门禁、实验设计、样本、运行记录、人工复核、Go/No-Go 结论、POC 报告生成与 Word 导出
- **交付**：G4 门禁、实施计划与里程碑、UAT 验收、上线检查、培训、问题与变更审批、交付文档生成与 Word 导出；UAT/上线检查表客户签收联动 G4-11
- **运营**：G5 门禁、指标目标、周期快照、价值记录、使用数据、续约与二期、价值报告/续约建议生成与 Word 导出
- **AI 助手**：访谈摘要、诊断报告/方案/PRD 骨架、知识库问答草稿；支持编辑、确认、拒绝与留痕；未配置大模型时自动回退规则草稿
- **成员**：项目负责人/成员/只读成员管理，项目级访问与写入控制

角色权限：`admin/director/pm` 才显示回收站、审计日志与知识审批入口；`consultant/tech_lead` 仍可做普通业务录入。项目配置成员后，仅成员可访问；只读成员不能写。

可观测性：前端请求自动带 `x-request-id`；接口错误框展示 `requestId`，可直接拿它去审计日志/服务端日志检索。

分页：项目列表、痛点、四维盘点、机会点、交付物、知识库均支持“加载更多”；审计日志为上一页/下一页。首屏 100 条（审计 50 条），按需追加。

代码分割：路由级（项目、知识库、标杆、回收站、审计、登录）与项目页签级（15 个页签）均使用 `React.lazy`；Markdown/mermaid 图表只在报告预览时加载。首屏入口约 240KB，mermaid 大块为按需资源。

页签体验：hover/focus 时预加载对应 chunk；按项目记住上次打开的页签（`localStorage`，切换项目互不影响）。

搜索：项目、客户、痛点、盘点、机会点、交付物、知识库、审计日志均为服务端搜索（300ms 防抖），与“加载更多”联用；搜索结果为空时显示空状态。

## 冒烟测试（Playwright）

```bash
npx playwright install chromium   # 首次
npm run e2e                       # 自动启动后端 8788 + 前端 5173
npm run e2e:ui                    # 交互模式
```

覆盖：登录/项目列表 → 服务端搜索 → seed 项目 → 痛点/方案/交付/运营/AI/报告页签 → 页签记忆 → 知识库检索 → PDF 导出 → 审计日志。
本地默认 `AUTH_REQUIRED=false`；若开启登录，测试会自动用 `zhang@hengzhi.ai / demo1234` 登录。
CI 已加 `e2e` job（Postgres service + db:reset + Chromium），失败时上传 `playwright-report`。

运维与监控：见根目录 [OPERATIONS.md](../OPERATIONS.md) 与 `ops/` 下的 Prometheus 抓取/告警示例。
- **风险与局限**：局限四分法、风险登记册、机会点依赖图（SVG）
- **报告**：14 项校验摘要、机会点依赖图、Markdown 预览、生成诊断报告/一页纸、导出 Word / 打印、PDF 后台生成与轮询下载、交付物版本、审批与外发记录、客户只读分享链接与访问明细
- **确认与签收**：客户对交付物/机会点/痛点/流程图的确认留痕，记录对象、确认人、方式与证据

## 已知边界

- PDF 由服务端无头 Chromium 渲染；前端使用异步任务（queued → running → done）并轮询下载，环境没有 Chromium 时任务失败，可继续用 Word 或浏览器打印。
- 报告用 GFM 渲染（表格 / 引用 / 代码块 / Mermaid），可切换源码；Markdown 与 Mermaid 都按需加载，不拖慢首屏。
- 业务流程编辑是 JSON 结构化编辑，不是拖拽画布；机会点依赖图是只读 SVG。
- 报告 §8.1 的 Mermaid 按需加载渲染（首次约 1MB，之后会话内缓存）；工作台另有 SVG 依赖图。
- 登录态已有；后端默认 `AUTH_REQUIRED=false`，生产设为 `true` 后前端会强制登录。组织级 `org_id` 过滤仍在 R1 W2 补。
- 有 Playwright 冒烟 10 条；没有组件级单测与视觉回归。
