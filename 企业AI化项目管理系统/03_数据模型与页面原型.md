# 03 · 数据模型与页面原型

> 版本 v0.1 ｜ 依据已确认决策：**无客户端门户 / 无录音转写 / 聚焦物流行业 / 多租户产品化 / 供应商内部单端**

> ⚠ **本文为 v1 基线。v2 增量（9 张新表、11 个字段、规则 R5 含 14 项校验）见 [05_数据模型v2.md](./05_数据模型v2.md)。**
> v1 的实体定义仍然有效，但 `roi_models`、`inventory_items`、`deliverables` 三张表已被 v2 扩展。

---

## 0. 本版范围与约束

| 已确认决策 | 对设计的直接影响 |
|---|---|
| **不做客户侧门户** | 系统只有内部用户。客户角色是**交付物的读者**，不是系统用户。用 `deliverable_shares` 记录"这份报告发给了谁、什么时候" |
| **交付物以电子文档人工提供** | `deliverables` 支持导出 Word/PDF；每次外发留痕，但不做在线确认（确认走线下，用 `confirmations` 登记） |
| **不做访谈录音转写** | `interviews.transcript` 手打录入；保留 `ai_summary` 字段（基于文本生成摘要） |
| **聚焦物流/供应链** | 盘点表、机会库、ROI 模板按行业打包，表上带 `industry_template_id` |
| **一开始按产品化设计** | 所有业务表带 `org_id`；RBAC + 租户隔离；API 预留开放能力 |
| **供应商内部单端** | 权限模型只需处理 5 个内部角色，不做外部访客 |

> **一句话：这版是"能卖给同行供应商的 SaaS 的 MVP"，不是"给客户用的系统"。**

## 1. 领域模型总览

```
Organization 租户（供应商企业）
│
├── User ──< Membership(role)
│
└── Client 客户企业 ──< Stakeholder 干系人
      │
      └── Engagement 项目/合作
            │
            ├── Interview 访谈 ──┐
            ├── PainPoint 痛点 ──┤
            ├── InventoryItem 盘点│
            ├── Confirmation 确认 │
            │                    │
            ├── Opportunity 机会点 ←── 关联痛点
            │     ├── Hypothesis 假设
            │     ├── Baseline 基线
            │     ├── ROIModel ROI
            │     └── TechBlocker 技术阻断
            │
            ├── Gate 门禁
            ├── Decision 决策记录
            ├── Risk 风险
            └── Deliverable 交付物 ──< DeliverableShare 外发记录
```

**核心主线：`Opportunity`。** 所有模块最终都服务于"给这个机会点建立可信的证据"。

## 3. 状态机与硬规则

### 3.1 Opportunity 状态机

```
candidate ──评分──> scored ──选中──> selected ──> designed
   │                                        │
   └──> parked（记录原因）                    └──> piloting ──失败──> killed
                                                      │
                                                      └──通过──> validated
                                                                     │
                                                                     └──> delivering
                                                                            │
                                                                            └──> live
                                                                                  │
                                                                                  └──> realized
                                                                                        │
                                                                                        └──> closed
```

### 3.2 四条硬规则（系统层面强制）

| # | 规则 | 触发点 | 违反后果 |
|---|---|---|---|
| **R1** | 无来源的痛点不能关联机会点 | 关联操作 | 阻断 |
| **R2** | 无基线时 ROI 置信度锁死 `low` | 保存 ROI | 自动降级 |
| **R3** | `has_tech_blocker=true` 禁止进入 `designed` | 状态变更 | 阻断，除非填写 `blocker_owner` |
| **R4** | 进入 `killed` 必须写 `kill_reason` | 状态变更 | 阻断 |

> 这四条是产品与普通 PM 工具的分水岭。**它们不是提示，是硬拦截。**

## 5. 页面清单与规格

### 5.1 页面总览（MVP 8 页）

| # | 页面 | 核心任务 | 优先级 |
|---|---|---|---|
| 1 | 工作台（项目列表） | 一眼看出哪些项目要出事 | P0 |
| 2 | 项目详情 | 当前阶段、门禁状态、待办 | P0 |
| 3 | 干系人 | 谁支持、谁抵触 | P1 |
| 4 | 访谈与痛点 | 录音没有，但有纪要；痛点可追溯 | P0 |
| 5 | 四维盘点 | 业务/数据/系统/组织 | P0 |
| 6 | 机会地图 | V×F 矩阵，一眼选出该做什么 | P0 |
| 7 | 机会点详情 | 评分、假设、ROI、阻断项 | P0 |
| 8 | 交付物中心 | 一键生成一页纸/诊断报告 | P0 |

### 5.2 逐页规格

#### 页面 1 · 工作台

- **目标用户**：项目总监、PM
- **顶部**：4 个数字卡（在跑项目 / 本周待过门禁 / 风险项目 / 本月成交）
- **主体**：项目卡片列表，每张显示：客户名、阶段、门禁状态、健康度灯、下次关键动作
- **健康度算法**：`红 = 有逾期门禁 或 风险≥3项`；`黄 = 门禁待审 或 周期超 1.3 倍`；`绿 = 正常`
- **空状态**：引导"新建客户 → 建项目 → 选行业模板"

#### 页面 2 · 项目详情

- **顶部**：客户名 + 阶段时间轴（S0–S5，当前高亮）
- **左侧**：门禁检查清单（打勾 + 未通过项标红）
- **右侧**：待办（谁、什么时候、做什么）、最近决策、风险 Top3
- **底部**：阶段产出物清单，未生成的显示"生成"按钮

#### 页面 3 · 干系人

- **主体**：四象限（影响力 × 态度）+ 列表
- **列表字段**：姓名、职位、角色类型、影响力、态度、关注点、是否已访谈
- **提醒**：`blocker` 或 `skeptic` 且未访谈 → 红色标记

#### 页面 4 · 访谈与痛点

- **左栏**：访谈列表（按人、按日期）
- **中间**：纪要正文（手打）+ AI 摘要区 + 原话摘录
- **右栏**：从本场访谈抽取的痛点
- **关键交互**：选中一段文字 → 点"标记为痛点" → 自动带 `source_ref`
- **痛点库视图**：表格 + 来源列 + 归并到机会点

#### 页面 5 · 四维盘点

- **四个 Tab**：业务 / 数据 / 系统 / 组织
- **数据 Tab 必须有**：`verified` 勾选 + 抽样结论输入框
- **进度条**：完成度按必填字段计算
- **阻断提示**：数据维度未验证 → 顶部黄条"机会点 ROI 置信度将被降级"

#### 页面 6 · 机会地图

- **视图切换**：矩阵图 / 表格
- **矩阵**：X 轴 = 可行性，Y 轴 = 价值，气泡大小 = 中性 ROI，颜色 = 优先级档
- **交互**：点气泡 → 右侧抽屉显示机会点卡摘要 → 点"详情"进页面 7
- **表格**：Code、名称、V、F、U、Score、档位、数据状态、阻断

#### 页面 7 · 机会点详情

- **头部**：名称 + 当前状态 + 优先级徽章 + 阻断提示
- **左列**：评分卡（V/F/U/D，附评分理由）、关联痛点
- **中列**：假设清单（带验证状态，可一键改状态）、基线数据、证据链接
- **右列**：ROI 卡片（保守/中性/乐观、回本周期、置信度）
- **底部**：状态流转按钮（受 4 条硬规则约束）

#### 页面 8 · 交付物中心

- **模板列表**：一页纸简报、诊断报告、ROI 表、路线图
- **生成流程**：选模板 → 预览变量填充 → 生成 → 编辑 → 导出 Word/PDF
- **外发记录**：谁、何时、通过什么渠道
- **版本**：每次生成递增，可对比

## 8. 三个关键交互

### 8.1 访谈 → 痛点 → 机会点

```
写纪要 → AI 摘要 → 划词标记痛点（自动带 source_ref）
      → 痛点库归并 → 选中若干痛点 → "生成机会点"
      → 系统预填：标题、关联痛点、初步 V/F 建议
      → 顾问修正评分并填理由
```

### 8.2 评分

V/F/U 三个滑块 → 实时算 Score 与档位 → **必须填 `score_rationale` 才能保存**。
D（数据就绪度）单独展示，不影响分数，但影响 ROI 置信度。

### 8.3 交付物生成

```
读取 engagement 全部结构化数据
  → 按行业模板组装
  → 生成草稿（AI 只负责过渡句与措辞）
  → PM 审核 → 导出
  → 登记外发记录
```

**关键：数字全部来自数据库，AI 不生成任何数字。** 这是可信度的底线。
