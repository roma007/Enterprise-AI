# 交付物样例说明

> 这份目录是**系统自动生成的交付物样例**，用于验证「结构化数据 → 模板 → 文档」这条链路是否成立。

> ⚠ **本目录含 v1 与 v2 两套口径。**
> v2 引入 `realization_factor`（收益实现形态）后，回本周期显著变化：
> OP-01 从 16.6 个月变为 **27.6 个月**，一期组合从 11.6 个月变为 **14.8 个月**。
> 详见 [../05_数据模型v2.md](../05_数据模型v2.md) 第 6.2 节。

## 为什么做这个样例

03 文档设计了 `deliverables` 表和"数字全部来自数据库、AI 只负责措辞"的原则。但设计得再漂亮，也要回答三个问题：

1. 生成出来的东西**能不能直接给客户看**？
2. 现有数据模型**够不够**支撑这份文档？
3. 哪些部分能自动，哪些必须人工？

这份样例就是对这三个问题的实测。

## 数据来源

全部取自 `prototype/index.html` 中「宏远国际物流」的项目数据：

- 5 场访谈（张伟 / 李强 / 王敏 / 刘芳 / 陈磊），合计 258 分钟
- 8 条痛点，每条带来源
- 4 维盘点（业务 4 / 数据 5 / 系统 4 / 组织 4）
- 6 个机会点，含评分、假设、基线、ROI
- G1 门禁 6/8 通过

## 阅读顺序建议

先看 `04_v1_v2迁移验证.md` 第一节（结论），再读 `v2/01_一页纸简报_v2.md`（3 分钟），然后按需翻 `v2/02_诊断报告_v2.md`。`03_生成能力缺口分析.md` 是 v1 的实测记录，解释了 v2 为什么长这样。

## 一句话结论

> **v1：自动化率 62%，能写"是什么"，写不了"所以呢"。**
> **v2.2：自动化率约 80%，且结论变了——效率类 AI 的 ROI 天生虚高，收入/现金类不打折；ROI 的 0.6 可以逐段拆开算给客户看。**
