### 1.3 技术债（必须在 R1 清掉）

| # | 债务 | 影响 | 处理 |
|---|---|---|---|

| 2 | 单租户：写接口取第一个组织 | 无法产品化售卖 | 登录态 + `org_id` 过滤 + RLS 或应用层强约束 |

| 4 | 没有 OpenAPI | 前后端/外部集成靠口口相传 | 生成 `openapi.json` + Swagger UI |

| 6 | 没有部署脚本 | 交付环境不可复制 | Docker Compose + 备份/恢复脚本 |
| 7 | 物理删除 | 误删不可恢复 | 软删除 + 回收站 + 审计 |

## 4. R2 · S2 方案设计（W4–W8）

### 4.1 目标

把 G1 选中的机会点，变成客户能批准、能报价、能验收的方案包。

### 4.2 范围

| 做 | 不做 |
|---|---|
| 方案说明书、架构、集成清单、PRD 骨架 | 详细技术设计文档的全部章节 |
| 工作量估算与报价（一次性 + 年运维） | 自动生成合同/法务条款 |
| 验收标准（基线 → 目标 → 方法） | 自动采集验收数据（S5 做） |
| 方案版本与评审 | 多供应商比价 |
| G2 一致性校验 | 客户在线协同编辑 |

### 4.3 数据模型（新增 8 张）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `solutions` | opportunity_id, version, status, scope, approach, architecture, deployment, security, assumptions, exclusions | 一个机会点可有多个方案版本 |
| `solution_components` | solution_id, name, type, vendor/build, description, effort_days | 方案组件 |
| `integrations` | solution_id, system, direction, protocol, fields, frequency, owner, risk | 接口需求清单 |
| `workload_estimates` | solution_id, role, days, rate, cost | 内部工作量，不进客户文档 |
| `quotes` | engagement_id, version, currency, one_time, annual_ops, payment_terms, valid_until, status | 报价头 |
| `quote_items` | quote_id, solution_id, description, qty, unit_price, amount | 报价行 |
| `acceptance_criteria` | solution_id, metric, baseline, target, method, owner, status | 验收标准 |
| `solution_reviews` | solution_id, reviewer, decision, comments, reviewed_at | 方案评审 |

### 4.4 API

| 模块 | 接口 |
|---|---|
| 方案 | `GET/POST /api/solutions`、`PATCH /api/solutions/:id`、`POST /api/solutions/:id/versions` |
| 组件 | `GET/POST/PATCH/DELETE /api/solutions/:id/components` |
| 集成 | `GET/POST/PATCH/DELETE /api/solutions/:id/integrations` |
| 工作量 | `GET/PUT /api/solutions/:id/workload` |
| 报价 | `GET/POST /api/engagements/:id/quotes`、`PATCH /api/quotes/:id`、`POST /api/quotes/:id/items` |
| 验收 | `GET/POST/PATCH /api/solutions/:id/acceptance-criteria` |
| 生成 | `POST /api/solutions/:id/generate`（proposal / architecture / prd / quote / acceptance） |
| 校验 | `GET /api/engagements/:id/g2-checks` |

全部支持 Word 导出；客户版隐藏内部成本/毛利。

### 4.6 页面

- 工作量与报价

- [ ] 客户侧方案书不含内部成本/毛利

## 5. R3 · S3 POC 验证（W9–W13）

### 5.1 目标

用真实数据回答“这事到底能不能成”，并留下可复核的证据。

### 5.2 范围

| 做 | 不做 |
|---|---|
| 实验设计、样本清单、基线/目标 | 自动训练模型 |
| 运行记录、人工复核、指标计算 | 自动标注平台 |
| 结论、Go/No-Go、终止/搁置 | 生产级 MLOps |
| POC 报告与导出 | 多模型自动对比（可后续） |

### 5.3 数据模型（新增 5 张）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `poc_experiments` | opportunity_id, hypothesis, method, sample_size, success_metric, threshold, start/end, owner, status | 实验设计 |
| `poc_datasets` | experiment_id, name, source, sample_count, fields, access_status, version | 样本数据 |
| `poc_runs` | experiment_id, run_no, config, dataset_id, started_at, finished_at, metrics jsonb, issues | 每次运行 |
| `poc_reviews` | run_id, reviewer, sample_count, accuracy, false_positive, notes | 人工复核 |
| `poc_conclusions` | experiment_id, decision, evidence, conditions, decided_by, decided_at | 结论与决策 |

### 5.4 API

- `GET/POST/PATCH /api/poc/experiments`
- `GET/POST /api/poc/experiments/:id/datasets`
- `POST /api/poc/experiments/:id/runs`、`POST /api/poc/runs/:id/reviews`
- `POST /api/poc/experiments/:id/conclude`
- `POST /api/poc/experiments/:id/generate`（POC 报告）
- `GET /api/engagements/:id/g3-checks`
- 结果 CSV 导入（复用导入框架）

### 5.5 交付物

- POC 实验设计
- POC 结论文档（含样本、指标、失败案例）
- Go/No-Go 决策记录

### 5.6 页面

- 实验设计
- 样本与基线
- 运行与复核
- 结论 / Go-No-Go
- POC 报告

### 5.7 G3 门禁

- [ ] 假设、样本、方法、成功阈值在实验前已确定
- [ ] 样本来源、数量、字段、访问状态可追溯
- [ ] 至少一次运行记录 + 人工复核

## 9. 数据模型演进路线

| Release | 新增表 | 累计约 |
|---|---|---|
| 现状 | S1 30 张 | 30 |
| R1 | `audit_logs`、`schema_migrations`（+可选 `benchmark_versions`） | 32–33 |
| R2 | solutions / components / integrations / workload_estimates / quotes / quote_items / acceptance_criteria / solution_reviews | 40–41 |
| R3 | poc_experiments / poc_datasets / poc_runs / poc_reviews / poc_conclusions | 45–46 |
| R4 | delivery_plans / milestones / tasks / uat_cases / uat_results / launch_checklists / trainings / issues / change_requests | 54–55 |
| R5 | metric_definitions / metric_targets / metric_snapshots / value_records / usage_records / renewal_risks | 60–61 |
| R6 | knowledge_articles / opportunity_library / template_versions / ai_runs | 64–65 |

**迁移原则：**

1. 只做加法：先加表/列，再回填，最后切读写；不直接删列。
2. 每个迁移有 `up` 和回滚说明；生产先备份。
3. `org_id` 回填作为 R1 的强制迁移；所有新表从第一天带 `org_id`。
4. 交付物、报告、审批保留快照，不用“当前数据”覆盖历史。
5. 复杂结构优先 `jsonb`（盘点属性、检查表、指标 JSON），稳定查询字段才建列。

## 12. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 客户数据拿不到 / 安全评审慢 | 高 | S3 延期 | R1 就发数据清单；先脱敏样本；合同写数据责任 |
| 关键干系人没时间 | 高 | 访谈/确认延期 | 项目负责人担保；固定周会；确认记录留痕 |
| 范围蔓延 | 中 | 周期失控 | 变更请求 + Gate 拦截；不在本期范围直接记 backlog |
| 方案/报价返工 | 中 | G2 延期 | 方案模板 + 评审；先做 1 个样板再批量 |
| POC 指标定义漂移 | 中 | 结论不可信 | 实验前锁定指标/阈值；运行记录不可改 |
| 多租户改造引发数据泄露 | 中 | 严重 | RLS + 自动化隔离测试；上线前安全评审 |
| 标杆数据不真实 | 高 | 报告可信度低 | 明确 `calibrated=false`；累计 ≥20 项目后校准 |
| 模板与代码分叉 | 中 | 报告不一致 | 单一模板注册表 + 生成快照；模板变更走版本 |
| LLM 数据出境 | 中 | 合规阻断 | 私有化/国内模型；默认脱敏；AI 产出人工确认 |
| 团队容量不足 | 中 | 全线延期 | 先保 R1/R2；R5/R6 可延后，不砍门禁 |

## 15. 估算口径与假设

- 人周 = 1 人 × 5 个工作日；估算为工程/设计/QA 净投入，不含客户等待和采购。
- 2 周一个迭代；每个 Release 末留 2–3 天缓冲。
- 假设现有 S1 代码可复用，不重写；S2–S5 以加法为主。
- 假设客户能提供至少 1 个真实项目做试点；没有试点时，周期不变但验收标准降级为“样例验证”。
- 估算误差 ±30%；范围变化时先更新本文，再改排期。
