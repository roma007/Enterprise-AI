# 07 · 多租户与交付架构

> 更新：2026-11-02
> 范围：诊断平台（供应商 SaaS）与客户交付系统（单租户）分别演进，不混为一个多租户应用。

---

## 1. 边界

### 1.1 诊断平台（本项目主平台）

- **租户 = 企业 AI 化解决方案供应商**。
- 任何供应商可自助注册，拥有独立组织、用户、客户、项目、诊断/方案/POC/交付/运营数据。
- 同一供应商可有多个账号（管理员、顾问、项目经理等）。
- **供应商之间完全隔离**，不共享客户、项目、报告、知识库与 AI 草稿。
- 形态：云托管多租户 SaaS。

### 1.2 客户交付系统（ai-copilot）

- 是**我方（平台运营方）交付给某个企业客户**的系统。
- 单租户：一个企业客户一套实例；可以由我方云上托管，也可以部署到客户内网。
- **不作为供应商 SaaS 对外开放**；别家供应商使用自己的交付系统，不在本项目范围。
- AI 应用按组件组合交付：不同企业客户启用不同组件，但编排权在我方交付团队。

### 1.3 因此不做的事

- 不把 ai-copilot 改造成“所有供应商共享的多租户 AI 平台”。
- 不做供应商之间的 AI 组件交易市场。
- 不让供应商看到其他供应商的交付实例。

## 2. 诊断平台租户模型

### 2.1 当前实现（M1 第一片）

- `organizations` 即租户；新增 `slug`、`status`、`settings`。
- 用户仍归属单一组织（`users.org_id`）；同供应商多账号通过 `memberships` 角色管理。
- 同一邮箱可以在不同供应商存在独立账号；登录时如命中多个组织，必须提供 `org_slug`。
- 新增 `POST /api/auth/register`：自助创建供应商租户 + 首个管理员 + 会话。
- 前端新增 `#/register`；登录页支持“组织标识（可选）”。
- 已加跨租户回归：注册、客户隔离、重复 slug、同邮箱多组织登录。
- **RLS 已启用**：受限角色 `ai_delivery_app` + 请求级 `app.org_id`；每个请求复用一条连接，结束后清理；`/api/system/db-context` 与直接 SQL 破坏性测试验证隔离。
- **PDF 队列已多实例化**：`pdf_jobs` + `SKIP LOCKED` 租约；API 可内联 worker，也可独立 `worker:pdf` 扩容。
- **PDF 存储已抽象**：local / S3(MinIO) 双后端；多主机部署使用 S3，本地/单机使用共享卷。已用本地 S3 兼容服务验证 PUT/GET/DELETE、跨进程读取与 API/worker 共享 PDF 缓存。
- **Redis 已接入**：登录限流与会话缓存优先 Redis，未配置回退内存；多实例部署必须配置。
- **多副本与发布**：Compose 提供 migrate job + 多副本 backend + nginx 网关；K8s 清单提供滚动升级、PDB、独立 worker。
- **故障演练已跑通**：`npm run soak:replicas` 验证持续压测（约 2000 QPS、P95 15ms）、压测中副本故障零失败、Redis 宕机回退、PDF 双 worker 分担。
- **备份恢复已演练**：`make drill-restore` 验证逻辑备份恢复、关键表行数与 RLS 隔离；`make drill-pitr` 验证 WAL 时间点恢复与前后对照。
- **SLO 与告警已落地**：`ops/slo.md` 定义可用性/延迟/PDF/连接池/备份 SLO，`ops/alerts.yml` 提供错误预算燃烧、队列积压、Redis、备份过期等规则。
- **滚动发布已演练**：`npm run drill:rollout` 在 3 副本 + nginx 上验证 readiness 切流、坏版本拦截与回滚；发布 0 失败、回滚 0 失败。
- **告警路由已演练**：`ops/alertmanager.yml` 定义 critical/warning/info 路由与同服务抑制；`npm run drill:alerts` 校验 17 条告警、9 个值班场景。
- 平台管理员（`users.is_platform_admin`）可查看租户列表、暂停/恢复、调整套餐；暂停会撤销该组织全部会话并阻止登录。
- 租户管理员可维护组织名称（`GET/PATCH /api/org`），前端 `#/org`；平台侧 `#/tenants`。

## 3. 客户交付系统组件化

### 3.1 组件契约

每个 AI 应用交付为独立组件：

| 字段 | 说明 |
|---|---|
| `component_id` / `version` | 如 `doc-ocr@1.3.0` |
| `image` / `offline_package` | 云上镜像 / 内网离线包 |
| `capabilities` | 能力标识，供工作流路由 |
| `config_schema` | 客户可配置阈值、字段、模型 |
| `io_contract` | 输入/输出 JSON Schema、回调 |
| `dependencies` | PostgreSQL / Redis / S3 / 模型服务 |
| `resources` | CPU/GPU/内存/存储 |
| `health` / `metrics` | 健康检查与指标 |
| `upgrade_policy` | 自动 / 人工 / 客户批准 |

### 3.2 交付形态

| 形态 | 说明 |
|---|---|
| 我方云托管（独立实例） | 每客户独立 namespace、DB、bucket；共享 K8s 集群 |
| 客户内网 | Helm / 离线包 + 客户 PostgreSQL/Redis/S3 兼容存储；至少多节点，不做单机 |
| 混合 | 数据面在客户内网，控制面（诊断平台）在云上，通过签名 API 回写结果 |

### 3.3 组件组合

- 由我方交付团队按客户场景选择：`doc-ocr`、`fee-anomaly`、`address-check`、`learn-queue` 等。
- 每个客户独立版本锁定与配置，升级需记录与可回滚。
- 组件不直接访问诊断平台数据库；只通过签名 API/Webhook 同步必要结果。

## 4. 高可用目标

### 4.1 诊断平台

- 多副本无状态 API + 负载均衡。
- 托管 PostgreSQL（主备/多 AZ/PITR）+ 连接池。
- Redis：登录限流、会话缓存、分布式锁。
- S3/MinIO：PDF、导出文件、附件。
- 外部队列：PDF/导出/批量任务；worker 独立扩缩容。
- 迁移独立 job，禁止应用启动时并发迁移。
- 滚动/蓝绿发布 + 健康/就绪探针。
- 日志聚合、Tracing、SLO、告警值班、定期恢复演练。

### 4.2 客户交付实例

- 云上：独立 namespace + 独立数据库/bucket；按客户配额限流。
- 内网：K8s 多节点或至少三节点容器平台；不使用单机 Compose 作为生产。
- 离线升级包、版本矩阵、远程健康回传（客户允许时）。
- 备份与恢复由交付团队按客户 SLA 执行。

## 5. 阶段与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| M1 | 租户模型、注册、slug 登录、RLS、生命周期 | 跨租户越权自动化测试全绿；暂停租户无法登录 |
| M2 | 组件目录、组合、云上/内网安装升级、回写 | 两个客户不同组件组合可独立部署与升级 |
| M3 | 无状态 API、Redis/S3/队列、多副本、PITR | 压测/故障演练通过；单副本故障不中断 |
| M4 | 计费、配额、运营后台、租户健康度 | 可开通/停用/计量/续费 |
