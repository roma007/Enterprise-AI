## 本地运行

```bash
# 0. Docker（推荐部署/演示）
cp .env.example .env
docker compose up -d --build
# 前端 http://localhost:8080；后端 http://localhost:8788

# 1. 不用 Docker：后端（PostgreSQL + Fastify）
cd backend
npm install
npm run db:reset      # 重建 ai_delivery 并灌入宏远样例
npm run dev           # http://127.0.0.1:8788

# 2. 前端（另开一个终端）
cd frontend
npm install
npm run dev           # http://127.0.0.1:5173
```

前端开发服务器把 `/api` 代理到 `127.0.0.1:8788`，不需要额外配 CORS。

## 已确认的产品决策

| 决策 | 结论 |
|---|---|
| 客户侧接入 | **不做门户**，交付物以电子文档人工提供，用外发记录留痕 |
| 访谈录音转写 | **不做**，手打纪要 + AI 摘要 |
| 行业范围 | 先聚焦**物流 / 供应链** |
| 商业化 | 一开始就按**产品化 / 多租户**设计 |
| 角色归属 | 「产品/技术负责人」= 供应商侧（乙方产品经理/架构师）；客户侧对应角色称「IT/数据负责人」 |
| 收益实现形态（v2.1） | **系统不判定**，顾问逐项手选；无默认值、必填理由（≥10 字）、必须署名 |
| 行业分位边界（v2.1） | **「落后」那条边界归落后**（低优 `>= p75`；高优 `<= p25`），其余边界归优 |
| 门禁缺口处理（v2.1） | **按比例分级**：缺口 <50% 阻断生成，50%–100% 附待确认清单放行 |
| ROI 敏感度（v2.2） | **因果传导链**，`realization_factor` = 各段系数连乘（不再手填） |
| 局限章节（v2.2） | **三分法**：金额类进正文紧跟 ROI、范围类紧跟痛点、方法类进附录、内部项不进客户文档 |

## 一句话概括

> 把企业 AI 化交付方法论固化成软件：以"AI 机会点"为主线，以"价值假设"为证据链，串起 **诊断 → 方案 → POC → 交付 → 运营**，并对客户输出他们看得懂、能拍板、能交差的东西。
