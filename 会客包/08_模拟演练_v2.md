## 4. 暴露的 4 个问题（全部已修）

### 问题 1 · 修正率算成 100%

第一次跑出来：

```
人工修正率    100.0%
```

**看起来像系统全错。** 实际只改了 1 个字段。

原因：分母写成了"被改过的字段数"，分子也是"被改过的字段数"，永远是 100%。
正确分母是"已确认单的全部非空字段"。

修复后：**0.4%**（1 处改动 / 约 270 个已填字段）。

> 这个 bug 很危险——它会让客户第一眼就否定整个系统。

### 问题 2 · 风险模拟与指标中心互相打架

```
指标中心：自动通过率 66.7%
风险模拟：自动通过率 100%
```

同一批数据，两个页面两个数。原因：指标中心按"分级审批结果"算，风险模拟另算了一套"置信度阈值"。

修复：风险模拟统一使用 `review_level == 'auto'`，与 C1 完全同源。

> **一个系统里两套口径，等于没有口径。**

### 问题 3 · 节省工时算成了"实际耗时"

代码写的是 `票量 × 自动通过率 × 平均确认耗时`，这是**花掉的时间**，不是**省下的时间**。

```
错误：0.71 小时 → 月省 933 元
正确：52.84 小时 → 月省 2,378 元（应为 基线−实际）
```

差了 **74 倍**。修复：`max(0, 基线 − 实际)`。

### 问题 4（最严重）· 0 错单被当成 0 风险

12 单自动通过、0 单被改，风险模拟直接输出：

> **"数据支持取消大部分人工确认"**

如果客户照着做，等于拿 12 个样本赌全年 2,000 单。

修复：加 **Laplace 平滑** —— `(错单+1)/(样本+2)`。

```
平滑前：错单率 0%   → 月损失 0       → 支持取消
平滑后：错单率 7%   → 月损失 79 万   → 不建议取消
```

> **这是整轮模拟最有价值的一条：**
> 系统不能因为"没见过错"就说"不会错"。样本量小的时候，必须主动承认不确定。

## 5. 现场还答不出来的 3 个问题（已闭环）

这一轮跑完后补做了，现在都能答：

| # | 客户问的 | 现在的能力 | 实现 |
|---|---|---|---|
| 1 | "改了箱型，但没写原单号" | 按 **箱号 / 客户 + 近 3 天** 反查原单；找到唯一候选就用，多个候选**不猜**，交人选择 | `find_amend_candidates` |
| 2 | "三票里有一票是改单" | 切分时把"原单 XX 有变"也当一票的起点，拆完逐票判是不是改单 | `AMEND_REF` + 逐票 `_resolve_amend` |
| 3 | "两个人同时确认会不会冲突" | 同内容重复提交 → 幂等返回；内容不同 → **409**，让人刷新后决定 | `version` + `ALREADY_CONFIRMED` |

**实测**

```
B1  反查（客户一致） → 箱型 40HQ→40GP，截港 12-07→12-10
    客户名保留「宏远国际货代」（没被"这票有变"污染）
B1' 两张原单都匹配 → 返回 2 个候选，不替用户决定
B2  切出 2 票：第1票新单，第2票识别为改单并给出 diff
B3  同内容重提 → 200 idempotent=true；改内容重提 → 409
```
