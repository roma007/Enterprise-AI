# 试点一 · 对账单 / 结算单抽取与差异解释

> 目标：用 2 周验证“AI 能不能把财务对账的入口和解释做掉”，而不是一上来做调度或单车毛利。
> 结论先行：**抽取用 OCR + 大模型 + 规则，差异判断用规则，解释用大模型；金额和结论必须可追溯、可人工复核。**
>
> **启动包（D1–D3）已就绪**：数据需求清单、金标模板、评测脚本、API/Schema 草图 → [`试点一/README.md`](./试点一/README.md)
>
> **D4 代码骨架已起步**：`app/statement.py`、`app/settlement_extract.py`、`app/diff_explain.py`；原始文本样本 strict 评测通过。

---

## 一、试点目标

把客户发来的：

- 客户对账单（应收）
- 外协/车队结算单（应付）

变成：

1. **结构化明细**：单号、客户/车队、期间、金额、运单号、箱号、车牌、数量、单价、扣款等
2. **与系统运单/合同价自动比对**
3. **差异清单 + 可能原因 + 建议动作**
4. **人工确认/修正/导出**

### 可量化目标

| 指标 | 目标 |
|---|---|
| 表头字段准确率 | ≥ 98% |
| 明细行字段准确率 | ≥ 95% |
| 明细行匹配召回率 | ≥ 98% |
| 金额合计准确率 | 100%（允许 0.01 元舍入） |
| 差异识别召回率 | ≥ 95% |
| 差异解释人工采纳率 | ≥ 70% |
| 单张对账单处理时间 | 比人工下降 ≥ 50% |
| 静默错误 | 0（所有未匹配/低置信必须显式标记） |

---

## 二、为什么先做这个

1. **复用现有底座**：`ai-copilot` 已有 OCR、字段抽取、规则校验、对账、外协结算
2. **不依赖 12–24 个月历史数据**：只需要客户提供近 3–6 个月对账单/结算单
3. **价值直接**：财务现在 2 人 × 5 天/月对账，试点目标是把“录入 + 找差异”压到小时级
4. **风险低**：不自动付款、不自动记账、不替代财务判断

---

## 三、范围

### 做

- 对账单：PDF 扫描件、照片、Excel/CSV、粘贴文本
- 结算单：同上
- 表头 + 明细行抽取
- 与运单/合同价匹配
- 差异分类：金额、缺行、多行、重复、税率、单价、数量、期间、客户/车队、舍入
- 差异解释：规则 + 大模型，输出“可能原因 + 证据 + 建议”
- 人工复核、修正留痕、CSV 导出

### 不做

- 不自动付款、不自动记账、不自动开票
- 不做发票认证/勾选
- 不做合同审阅
- 不做调度/成本归集/单车毛利
- 不让大模型直接计算金额或做法律结论

## 七、样本要求

| 项目 | 要求 |
|---|---|
| 数量 | 对账单 ≥ 30 份；结算单 ≥ 30 份 |
| 金标 | 各 ≥ 10 份人工逐字段标注 |
| 格式 | PDF 扫描、手机照片、Excel/CSV、粘贴文本，至少覆盖 3 种 |
| 期间 | 近 3–6 个月，覆盖不同客户/车队 |
| 难点 | 多页、盖章、手写、合并单元格、重复行、扣款、税率不同 |
| 隐私 | 脱敏客户名/金额/车牌；优先客户内网或我方沙箱；不把原文发外部模型（除非客户书面同意） |
| 评测 | 留出集不参与调参；调优集与留出集分开 |

## 九、差异解释的设计

### 9.1 分工

- **规则**：判断差异类型、金额、匹配关系（确定性）
- **大模型**：把结构化差异 + 历史案例 + 规则说明，转成“人话解释”
- **人**：确认原因、决定动作

### 9.2 输出 JSON

```json
{
  "difference_id": "diff-001",
  "type": "amount_mismatch",
  "waybill_no": "HY20261001001",
  "statement_amount": 2600.00,
  "system_amount": 2400.00,
  "delta": 200.00,
  "evidence": ["对账单第 2 行", "运单应收 2400", "税率 9%"],
  "possible_causes": [
    "对账单含 200 元附加费，运单未包含",
    "运单金额录错"
  ],
  "suggested_action": "先核对附加费条款；若合同包含，则补录运单费用",
  "confidence": 0.72,
  "source": "llm+rule"
}
```

### 9.3 护栏

- 大模型不得生成新金额；金额只能引用规则计算结果
- 解释必须带证据（行号/字段/规则）
- 置信度低时只给“可能原因”，不下结论
- 大模型失败自动回退规则模板
- 所有解释可人工编辑，留痕

## 十、验收指标

| 维度 | 指标 | 目标 | 测量方式 |
|---|---|---|---|
| 抽取 | 表头字段准确率 | ≥ 98% | 金标逐字段 |
| 抽取 | 明细行字段准确率 | ≥ 95% | 金标逐行 |
| 抽取 | 金额合计准确率 | 100% | 合计比对 |
| 匹配 | 明细行匹配召回率 | ≥ 98% | 与运单/合同价 |
| 差异 | 差异识别召回率 | ≥ 95% | 人工标注差异 |
| 差异 | 差异误报率 | ≤ 5% | 人工复核 |
| 解释 | 人工采纳率 | ≥ 70% | 20 条抽样评分 |
| 效率 | 单张处理时间下降 | ≥ 50% | 基线 vs 试点 |
| 安全 | 静默错误 | 0 | 未标记的低置信/未匹配 |
| 体验 | 财务满意度 | ≥ 4/5 | 问卷 |

## 十一、风险与应对

| 风险 | 应对 |
|---|---|
| 格式太多 | 先支持 Top 3；其余人工/后续适配 |
| OCR 质量差 | 预处理、置信度、低置信强制复核 |
| 差异原因不确定 | 只给“可能原因”，不强行下结论 |
| 客户数据不能出内网 | 客户内网部署或脱敏沙箱 |
| 财务不信任 | 先辅助、可回退、全量留痕；不自动记账 |
| 大模型编造 | 金额/差异由规则计算；解释带证据；失败回退模板 |
| 样本不足 | 先拿 10 份金标；不足则延长数据准备，不进入开发 |

## 十三、Go / No-Go

**Go：**

- 表头 ≥ 98%，明细 ≥ 95%，金额 100%
- 差异召回 ≥ 95%，误报 ≤ 5%
- 解释采纳 ≥ 70%
- 时间下降 ≥ 50%
- 财务愿意在下一批真实账单上试用

**No-Go / 回退：**

- 关键字段低于 90%
- 差异漏报严重
- 客户不愿提供稳定样本
- 数据不能脱敏/不能出内网且无本地环境

> 不达标就回到“人工 + 规则”，不把不确定的东西推到生产。
