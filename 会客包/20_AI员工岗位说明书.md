# 20 · AI 员工岗位说明书

> 用途：把系统能力翻译成客户听得懂的「岗位」，而不是「模型/功能清单」。
> 边界：AI 员工是**接手重复动作**，不是替代人；金额、账龄、法律结论必须由规则计算、人确认。
> 适用：集卡 / 拖车 / 货代 / 综合物流的单证、财务、应收岗位。

---

## 一、先看一张表

| 岗位 | 接手什么 | 交给谁 | 不做什么 |
|---|---|---|---|
| **AI 单证员** | 托书 / 发票 / 对账单的读取、字段抽取、异常提示 | 单证员确认后入系统 | 不自动入 TMS、不替人确认 |
| **AI 对账员** | 对账单/结算单 ↔ 运单/合同价的匹配、差异分类、原因解释 | 财务逐条采纳/修改/忽略 | 不自动调账、不自动付款/开票 |
| **AI 催收员** | 应收台账分档、客户风险、催收清单、话术模板/润色 | 财务核对后复制/发送 | 不自动发函、不做法律判断 |

> 一句话：**AI 负责“读”和“提示”，规则负责“算”和“查”，人负责“确认”。**

---

## 二、AI 单证员

### 岗位目标

把客户发来的托书、发票、对账单，从微信/图片/PDF/Excel 变成**带置信度和异常提示的结构化草稿**，让单证员从“找数、抄数”变成“只看异常”。

### 输入

- 企业微信文字（可分条）
- 手机拍照 / 截图 / 扫描件
- PDF / Excel / CSV
- 网页粘贴
- 批量导入（一次几十份）

### 输出

- 字段值 + 每个字段的置信度
- 规则挑出的异常：箱号校验位、截港已过、箱量不符、地址冲突、电话格式
- 待人工确认的清单
- 确认后写入系统，保留操作人、时间、修改 diff

### AI 与规则怎么分工

| 环节 | 谁做 |
|---|---|
| 从图片/文字里认字段 | 大模型 + OCR |
| 箱号 ISO 6346、箱型、截港、地址、电话 | 规则 |
| 低置信度/阻断项 | 规则分级，转人工 |
| 最终确认 | 人 |

### 不做什么

- 不自动把草稿写进客户 TMS
- 不替单证员点“确认”
- 不修改客户原文
- 不在没有原文依据时“猜”字段

### 适合的客户

- 单证/操作 2 人以上
- 月单量几百票以上
- 托书来源杂：微信、图片、PDF、Excel 都有
- 错箱、截港、地址错误有实际罚款或返工

### 验收看什么

- 字段级准确率（用客户真实样本）
- 单票人工修正时间
- 箱号/截港/地址异常拦截数
- 确认后回溯率（能不能追到原文、人、时间）

## 三、AI 对账员

### 岗位目标

把客户对账单/外协结算单与运单、合同价逐条比对，先给出**差异清单 + 原因 + 建议动作**，财务只看异常。

### 输入

- 客户对账单（PDF/照片/Excel/粘贴）
- 外协车队结算单
- 运单/订单记录
- 合同价/报价表

### 输出

- 差异分类：金额不符、缺行、多行、重复、税率/单价/数量/期间/主体不符、舍入、无合同价
- 每条差异的证据、可能原因、建议动作
- 人工复核记录：采纳 / 修改后采纳 / 忽略 + 备注
- 可导出的差异表

### AI 与规则怎么分工

| 环节 | 谁做 |
|---|---|
| 读对账单/结算单 | OCR + 大模型 |
| 匹配运单/合同价、算差额 | 规则 |
| 差异原因解释 | 可选大模型；失败回退规则模板 |
| 采纳/忽略 | 人 |

### 不做什么

- 不自动调账、不自动付款、不自动开票
- 不让模型直接计算金额或做法律结论
- 不把“模型解释”当成“差异定性”

### 适合的客户

- 每月对账 1 人 × 3 天以上
- 对账单格式多、客户多
- 外协车队多、合同价复杂
- 差异靠 Excel 手工标

### 验收看什么

- 应发现的差异是否都出现（召回）
- 标出来的差异有多少其实没问题（误报）
- 单张对账单复核时间
- 每个决策能否追到人、时间、依据

## 四、AI 催收员

### 岗位目标

把应收台账变成**催收优先级和可执行话术**，让财务知道“先催谁、说什么”，而不是只给一张账龄表。

### 输入

- 应收台账：客户、单号、应收、已收、到期日

### 输出

- 账龄分档：未到期 / 1–30 / 31–60 / 61–90 / 90+
- 客户风险等级：正常 / 提醒 / 催收 / 重点催收
- 催收清单：按逾期金额、最长逾期天数排序
- 话术模板：提醒 / 催收 / 重点催收三档
- 可选 AI 润色：只改措辞，数字由规则锁定，默认关闭
- 复制记录 / 后续跟进待办（可接通知）

### AI 与规则怎么分工

| 环节 | 谁做 |
|---|---|
| 账龄、逾期天数、金额、占比 | 规则 |
| 分档、排序、等级 | 规则 |
| 话术模板 | 规则 + 占位符 |
| 话术润色 | 可选大模型；不合规/不可用回退模板 |
| 发送/法律判断 | 人 |

### 不做什么

- 不自动发函、不自动打电话
- 不承诺减免、延期、折扣
- 不做法律结论
- 不按“模型觉得”改变金额或账龄

### 适合的客户

- 应收台账在 Excel
- 逾期靠人记
- 客户多、账期不一
- 催收没有优先级

### 验收看什么

- 逾期客户覆盖率
- 催收跟进记录完整率
- 回款天数变化（需客户基线）
- 话术复制/使用次数（不能只看“生成了多少”）

---

## 五、明确不做的“AI 员工”

| 不做的岗位 | 原因 |
|---|---|
| AI 调度员 | 依赖货源池、司机意愿、GPS；不是单点模型能解决 |
| AI 客服 | 需要实时轨迹/在途数据；现在没有 |
| AI 数字人/内容创作 | 与集卡单证、对账、回款无关 |
| AI 自动付款/自动开票 | 财务合规不允许，必须人确认 |

---

## 六、怎么卖

不要按“模型调用次数”卖，按**岗位 + 试点**卖：

1. 先选一个岗位做 2 周试点（通常 AI 单证员）
2. 用客户 20–50 份真实样本跑字段准确率和修正时间
3. 达标再扩到对账/催收
4. 不达标就停，不进入下一阶段

一句话：

> **先让一个 AI 员工上岗，用你们的单据考核；考核不过，不上第二个。**
