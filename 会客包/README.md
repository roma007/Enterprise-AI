## 二、为什么先做 02

1. 成本最低（0.5 天），对会客的影响力最大——老板只信"你替我想清楚了"，不信功能演示。
2. 它的结论会反向决定 demo 做多大、先做哪个场景（若财务优先级被抬升，04a/04b 顺序可换）。
3. 它同时也是 `03 提问清单` 的来源：机会地图里每个"前置条件"就是一道必问。

## 三、02 的核心结论（摘要）

| 结论 | 内容 |
|---|---|
| 两域关系 | 业务与财务不是两条线，是**上下游**。财务 AI 的上限 = 业务数据结构化的程度 |
| 根节点 | **B1 托书结构化录入** 是唯一不依赖前置数据的点，必须第一期 |
| 第一期 | B1（业务）+ F1（财务，仅识别校验）= 2 个点，3 个月可算账 |
| 一期收益 | 25–45 万 / 年（100 台车假设） |
| 明确暂缓 | B7 智能调度、经营分析大屏、替客户裁人 |
| 收尾目标 | 不是成交，是拿到 **200 份真实托书 + 1 名内部 owner** |

## 四、纪律（防止会客包变成产品）

- ❌ 不做多租户（客户侧单租户，一客一实例）；登录与四角色已具备
- ❌ 不做工具库 / 插件机制 / 低代码平台；运行级配置只放开真实接线的项
- ❌ 本阶段不接客户 TMS / 财务软件；有接口文档后按 C2 评估
- ❌ 不编造客户案例；样本来源必须标注（合成 / 公开 / 客户提供）
- ✅ 所有对外数字标注口径与来源；财务侧只讲公式，不讲金额
